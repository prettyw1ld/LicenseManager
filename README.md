## Что умеет сервер

1. После проверки логина и пароля из БД выдаёт клиенту **уникальный код** вида `XXXX-XXXX-XXXX-XXXX`.
2. Проверяет, есть ли свободное **место для лицензии** (например, 5 мест: шестой клиент получает ошибку `NO_SLOTS`).
3. Команда `list` показывает подключённых клиентов: дата и время подключения, продолжительность, IP, порт, уникальный код, состояние.
4. Через заданное время **отключает клиента** (`EXPIRED`), чтобы тот переподключился и получил новый код.
5. Команда `kick` отключает выбранного клиента.
6. При запуске спрашивает настройки: IP и порт, количество кодов (лицензий), время до отключения, время на подтверждение кода, строку подключения к БД.
7. **Чёрный список** (оценка «хорошо»): по логину или IP. Клиент из чёрного списка получает ошибку `BLACKLISTED`, а уже подключённый отключается.
8. **Логин и пароль из БД** (оценка «отлично»): код выдаётся только после успешной аутентификации. Пароли хранятся как SHA-256 с солью.

## Запуск

1. Выполнить `Database/LicenseManager.sql` в SQL Server Management Studio (создаёт БД `LicenseManager` и тестовых пользователей).
2. Открыть `LicenseManager.slnx` в Visual Studio 2022 (17.13+) и запустить проект `LicenseServer`
   или из консоли: `dotnet run --project LicenseServer`.
3. Ввести настройки (Enter — значение по умолчанию). Введённые настройки сохраняются в `settings.json`.

Тестовые пользователи (пароль у всех `12345`): `damir`, `client`, `user1`, `user2`, `banned` (в чёрном списке).

### Команды сервера

```
list                     — подключённые клиенты
kick <№|код|логин>       — отключить клиента
ban <№|логин|IP> [прич.] — добавить в чёрный список и отключить
unban <логин|IP>         — убрать из чёрного списка
blacklist                — показать чёрный список
users                    — пользователи из БД
adduser <логин> <пароль> — добавить пользователя
settings | clear | help | exit
```

## Протокол обмена

**Транспорт:** TCP. **Формат:** один JSON-объект в кодировке UTF-8 на строку, строка заканчивается `\n`.
У каждого сообщения есть поле `type`. Регистр значения `type` не важен, но лучше писать заглавными.
Даты передаются в ISO 8601 с часовым поясом: `2026-11-18T15:30:00+05:00`.

### Порядок работы клиента

```
Клиент                                   Сервер
  | --- TCP connect ---------------------> |
  | <-------------------------------- HELLO |
  | --- AUTH {login,password} -----------> |  проверка чёрного списка, пароля, мест
  | <------------------------- CODE {code} |  (или ERROR + DISCONNECT)
  | --- CONFIRM {code} ------------------> |  нужно успеть за confirmTimeoutSeconds
  | <-------------------------- CONFIRMED |
  | --- CHECK {code} (каждые ~5 с) ------> |
  | <-------------------- STATUS {blocked} |
  | --- RENEW {code} (по желанию) -------> |
  | <--------------------- CODE {новый код}|  новый код тоже надо подтвердить CONFIRM
  |              ...                       |
  | <------------- DISCONNECT {EXPIRED}    |  время вышло: переподключиться и пройти AUTH заново
```

Сервер может прислать `DISCONNECT` в любой момент (а не только в ответ на запрос), поэтому клиенту нужно
читать сообщения в отдельном цикле/потоке и обрабатывать их по полю `type`.

### Сообщения клиента → сервер

| type | Поля | Когда |
|---|---|---|
| `AUTH` | `login`, `password` | сразу после `HELLO` |
| `CONFIRM` | `code` | после каждого полученного `CODE` |
| `CHECK` | `code` | периодически: статус и проверка блокировки |
| `RENEW` | `code` (текущий) | запросить новый код без переподключения |
| `BYE` | — | корректное отключение |

```json
{"type":"AUTH","login":"damir","password":"12345"}
{"type":"CONFIRM","code":"YS6U-2AJU-K2RM-PMCN"}
{"type":"CHECK","code":"YS6U-2AJU-K2RM-PMCN"}
{"type":"RENEW","code":"YS6U-2AJU-K2RM-PMCN"}
{"type":"BYE"}
```

### Сообщения сервер → клиент

**HELLO** — сразу после подключения:
```json
{"type":"HELLO","server":"LicenseServer","version":1,"authRequired":true,"sessionId":1,
 "clientIp":"127.0.0.1","clientPort":58504,"connectedAt":"2026-11-18T15:59:26+05:00"}
```

**CODE** — ответ на `AUTH` и `RENEW`:
```json
{"type":"CODE","code":"YS6U-2AJU-K2RM-PMCN","login":"damir","clientIp":"127.0.0.1","clientPort":58504,
 "connectedAt":"2026-11-18T15:59:26+05:00","confirmTimeoutSeconds":30,"expiresInSeconds":300}
```

**CONFIRMED** — ответ на `CONFIRM`:
```json
{"type":"CONFIRMED","code":"YS6U-2AJU-K2RM-PMCN","expiresInSeconds":287}
```

**STATUS** — ответ на `CHECK`:
```json
{"type":"STATUS","code":"YS6U-2AJU-K2RM-PMCN","login":"damir","clientIp":"127.0.0.1","clientPort":58504,
 "connectedAt":"2026-11-18T15:59:26+05:00","durationSeconds":13,"expiresInSeconds":287,
 "confirmed":true,"blocked":false}
```
Если `blocked` = `true`, следом придёт `DISCONNECT` с причиной `BLACKLISTED`.

**ERROR** — ошибка запроса:
```json
{"type":"ERROR","error":"NO_SLOTS","message":"Нет свободного места для лицензирования (занято 5 из 5)."}
```

| error | Значение | Соединение |
|---|---|---|
| `BAD_REQUEST` | не JSON, нет полей, неизвестный `type` | остаётся |
| `AUTH_FAILED` | неверный логин/пароль (3 попытки) | после 3-й закрывается |
| `BLACKLISTED` | логин или IP в чёрном списке | закрывается |
| `NO_SLOTS` | нет свободных лицензий | закрывается |
| `ALREADY_CONNECTED` | этот логин уже получил лицензию | закрывается |
| `NOT_AUTHORIZED` | `CONFIRM/CHECK/RENEW` до `AUTH` | остаётся |
| `INVALID_CODE` | прислан не тот код | остаётся |
| `SERVER_ERROR` | ошибка сервера/БД | остаётся |

**DISCONNECT** — сервер закрывает соединение:
```json
{"type":"DISCONNECT","reason":"EXPIRED","message":"Время действия кода истекло. Подключитесь заново, чтобы получить новый код."}
```

| reason | Значение | Что делать клиенту |
|---|---|---|
| `EXPIRED` | вышло время лицензии | переподключиться и пройти `AUTH` заново |
| `CONFIRM_TIMEOUT` | код не подтверждён вовремя | переподключиться |
| `KICKED` | отключён администратором | показать сообщение |
| `BLACKLISTED` | добавлен в чёрный список | показать сообщение, не переподключаться |
| `REJECTED` | отказ (после `ERROR`) или не авторизовался за 60 с | показать сообщение |
| `SERVER_SHUTDOWN` | сервер остановлен | показать сообщение |
| `CLIENT_BYE` | ответ на `BYE` | — |

### Таймауты

* На `AUTH` после подключения — 60 секунд.
* На `CONFIRM` после получения кода — `confirmTimeoutSeconds` (задаётся при запуске сервера).
* Время жизни лицензии — `expiresInSeconds`, отсчитывается с момента первой выдачи кода; `RENEW` его не продлевает.

### Проверка без клиента

Можно подключиться любым TCP-терминалом (PuTTY в режиме Raw, `ncat`, `telnet`) и вводить JSON построчно:
```
ncat 127.0.0.1 5050
{"type":"AUTH","login":"damir","password":"12345"}
```
